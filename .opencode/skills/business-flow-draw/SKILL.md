# 业务流程图绘制与维护

产出**可编辑的 `.drawio`**，不是图片。业务内容以项目内的业务设计说明书为准，
通用画图规则以本 skill 的 references 为准。

## 何时用

- 用户要求"按设计说明书改图 / 画业务流程图 / 生成 draw.io 图"
- 需要维护 `docs/diagrams/` 下的既有图

## 工作流

1. **读业务**：`docs/business/<图名>业务设计说明书.md` —— 业务对错、禁则、验收软检查判据
2. **读规范**：`references/flowchart-guidelines.md` —— 线型语义、配色、走线约束
3. **改图源**（分批，见下方「骨架+分批写入」）：只改 `docs/diagrams/gen-*.py`（文案/坐标/样式/连线），**禁止手改 `.drawio`**
   - 3a. **首笔只写骨架**：helpers（`esc/node/edge`）、样式常量、标题、图例、装配段；不含业务节点
   - 3b. **分批补业务节点与连线**：每批 ≤10 个元素（节点或边），**每批后立即跑一次生成+校验**，用校验脚本的实际输出决定下一批怎么写
   - 3c. **禁止单轮输出整个 `gen-*.py`**
4. **生成**：`python3 docs\diagrams\gen-<标识>.py docs\diagrams\<标识>.drawio`（同标识配对）
5. **校验**：按 `references/diagram-checklist.md` 跑硬门槛三条
6. **收尾**：业务有变动 → 同步更新业务设计说明书与其中的变更记录

### 骨架+分批写入（硬规则）

超长单轮（一次写完整个 gen 脚本，或在推理里手工验算坐标/交叉/文字宽度）会撞上游
**约 300 秒的流上限**，导致整轮输出作废、反复 `interrupted`、零产出。因此：

- ❌ 禁止单轮写完整个 `gen-*.py` —— 先骨架，再分批（每批 ≤10 个元素），批间跑校验迭代
- ❌ 禁止在推理/回复里手工推演几何（交叉、越界、文字宽度）来"证明"图没问题 ——
  几何对错**只认 `validate.py` 与 `check-diagram.py` 的输出**，靠反复跑校验迭代

#### 首笔前置禁令（针对"写之前就烧完 300s"）

实测教训：2026-11 复测中模型复述了本规则，却在**首笔 write 之前**先做全图设计
（布局/坐标/配色/节点清单），连续 4 轮 ×~305s 纯推理被掐断、约 21 分钟零产出。
因此：

- 读完说明书与规范后的**下一轮必须发出骨架 write 调用** —— 骨架只含
  helpers / 样式常量 / 标题 / 图例 / 装配段，**不含任何业务节点，不需要业务设计**；
  写骨架前**禁止开做全图设计**（布局方案、坐标推演、配色方案、节点清单、文案措辞）
- 每批的业务设计**只在写该批的那一笔里进行**：想好这批 ≤10 个元素的坐标就直接写，
  写完立即 gen+validate，**让校验输出决定下一批**，不在推理里预演后续批次
- **想读文件就发 read 调用**，不许在推理里"打算读"（"Let me read validate.py…"说了不发，
  推理流会先撞上限）；README / 说明书 §5§6 同步属**收尾步骤**，首笔之前禁止规划

## 硬性禁止

- 禁止直接编辑 `.drawio`（会被下次生成覆盖）
- 禁止画入技术细节：接口路径、类名、框架名、Filter、Handler、Token 内部实现
- 禁止把本应独立的两个判断合并成一个判断框（业务说明书会指明哪些必须独立）
- 禁止单轮写完整个 `gen-*.py`、禁止手工推演几何（见上方「骨架+分批写入」）

## 依赖

- **全局 `drawio-skill`**：提供 `.drawio` XML 规范、样式词汇、`validate.py` 几何校验
- 本 skill：提供项目化的流程、验收清单、业务说明书模板

## 关键约定

- **坐标与文案只写在 `gen-*.py`**，说明书中不复制坐标表（避免两份不同步）
- 容器内子节点用**相对坐标**，连线 waypoint 用**页面绝对坐标**
- 菱形进出必须用顶点锚点（上 `0.5/0`、下 `0.5/1`、左 `0/0.5`、右 `1/0.5`）
