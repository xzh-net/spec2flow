# 经验教训（面向修改者，使用者不需要读）

> 本文件记 **`git log` 表达不了的东西**：为什么这样改、旧结论何时被推翻、踩过什么坑、下次怎么避。
> `git log` 记"改了什么"（文件、行数、提交号）；本文件只记"为什么改、代价多大、复发时看哪"。
> 纪律：每条都要能回答"读者据此下次能少犯什么错"——答不出的不写。
> 使用者的操作指导在 [README.md](../README.md) §1；本文件只属维护侧，使用者侧不引用它。

**条目格式（新增条目照抄字段，不缺项）**：

```markdown
### 日期 · 一句话摘要
- 现象：（用户看到什么、损失多大，带实测数据）
- 根因：（因果链，指到最底层；规则本来就有的要写明"为什么没起作用"）
- 修复：（改了哪几处、各属哪一层；为什么这么分层）
- 遗留与复发信号：（下次见到什么现象 = 这个坑又来了，去哪看处置）
- 快照：（commit hash 或"本批未提交"；验收实测结果）
```

### 2026-11-09 · 画图死循环：单轮输出过大撞上游 ~300s 流上限

- **现象**：画第二张图（`gen-message-push.py`）时整轮零产出——连续 **41 次**
  "The previous response was interrupted"，从 11-08 13:10 持续到 11-09 10:53（**约 22 小时**）；
  每轮跑满 **305 秒整**、错误清一色 `provider.invalid-output: OpenAI Chat stream ended without finish_reason`、
  **0 工具调用**。同病早有前科但未循环：11-05 画第一张图时单轮 reasoning 冲到
  **319,537 字符 / 36 分钟**（`finish: length`）——这就是"每次画图都执行很长时间"的体感来源。
  反观成功轮次：reasoning 仅 190~3000 字符、13~30 秒就发出 write/edit/shell——差别不在任务难度，在**是否先动手**。
- **根因**：因果链三层叠加——
  ① 模型把**机器校验目标**（0 交叉 / 0 溢出）内化成了**推理前提**，在 reasoning 里逐条手工验算几何
  （单轮 25,854 → 46,377 字符且越滚越大，因为失败轮 reasoning 留在上下文里，下次"想得更全"），
  烧光全部时间预算，write 调用永远发不出来；
  ② 上游约 **300s 流式上限**掐断整轮（status 200，非报错，是"没说完就没了"），该轮判为作废；
  ③ 自动续跑注入 "Continue from where you left off" **没有降级策略**——模型带着膨胀上下文从头再推演 → 死循环。
  **关键教训：规则本来就存在**——`diagram-checklist.md` 排错表旁就写着"靠反复跑校验迭代，不要手工证明不交叉"——
  但它只在**出错后**才被读到，而病因发生在**推理阶段**：**规则存在，位置错了**。
- **修复**：分层三处 + 环境两处，零重复正文（守本仓库单一权威源传统）——
  ① skill `SKILL.md`：工作流第 3 步拆为 3a 骨架 / 3b 分批（≤10 元素/批、批间跑校验）/ 3c 禁止单轮全量，
  并新增《骨架+分批写入（硬规则）》与硬性禁止一条（**指导**：怎么分批）；
  ② `references/diagram-checklist.md` 排错表首行：现象 → 原因 → 修法（**兜底**：出错了怎么修）；
  ③ 本项目 `AGENTS.md`：改图约定第 6 条 + 构建与验证⚠️（**警示**：会话启动即自动加载，出现在病因发生之前）；
  ④ `scripts/check-diagram.py`：`sys.stdout.reconfigure(encoding="utf-8")`（Windows GBK 乱码导致验收判据
  `OK: 无标签溢出…` 无法精确匹配）；
  ⑤ `README.md` 命令速查补 `Set-Location`（相对路径命令在仓库根目录执行报 `No such file`）。
  另修环境项：全局 `opencode.jsonc` 的 penpot MCP `enabled: false`（服务器不可达，每次会话启动白等 20~85 秒重试）。
  **三层分工**：AGENTS.md = 警示（为什么不能那样做 + 实测代价 + 指到细则）、SKILL.md = 指导（具体怎么分批）、
  checklist = 兜底（现象识别与处置）——互为指针，不抄正文。
- **遗留与复发信号**：上游 ~300s 流上限是提供方侧行为，改不了，**只能靠拆小单轮输出规避**；
  画图请**开新会话**，勿在超长历史会话里画（失败轮 reasoning 全部留在上下文，会加剧膨胀）；
  模型侧根因（追求"一次画对"）只能靠规则持续压制，不能假设已根除。
  **复发信号 = 又见连续 `interrupted` 或 `stream ended without finish_reason`** →
  看 `diagram-checklist.md` 排错表首行，按《骨架+分批写入》重来，**不要重试同样的全量写法**。
- **快照**：修复批 commit `59caa4b`（SKILL/checklist/AGENTS/check-diagram/README + 配置项 penpot 暂停在全局 opencode.jsonc，不入库）；本条目随文件首建同批提交。验收实测：三硬校验全绿（生成 32 nodes / 22 edges、几何 0 error / 0 warning /
  score 0、文字自检 `OK: 无标签溢出、无同层重叠` 且**不加**编码环境变量）；全仓 markdown 断链 0。
